# Independent alpha behavioral test contract

These tests derive their expectations from the user’s narrowed alpha request, not from the current implementation. They exercise public API calls, CLI subprocesses, and persisted artifacts. Fixture projects intentionally omit installed application dependencies: a local static analyzer must inspect syntax without executing fixture code.

## Gating alpha scenarios and faults rejected

| Scenario                         | Observable contract                                                                                                                                                                                                 | Example faulty implementation rejected                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| TypeScript/JavaScript discovery  | Selected TS, TSX, JS, and JSX files use root-relative POSIX paths; excluded files and outside-root symlinks do not enter the map                                                                                    | Recursive walking that follows symlinks, includes `.ai`/build output, or stores absolute paths                   |
| Exact core index                 | Imports, renamed imports, exports/re-exports, CommonJS, public signatures, environment-variable names, references/calls, classes/methods, source locations, and stable unique IDs are present                       | Regex-only parsing that loses aliases, overloads, calls, class qualification, or duplicate names                 |
| React index                      | Typed component props, `useState`, `useReducer`, `useMemo`, `useCallback`, `useEffect`, dependency arrays, memo wrapping, and rendered JSX edges are represented                                                    | Merely labeling capitalized functions as components without state/hook/dependency/render evidence                |
| Parser adapter boundary          | The compiler-backed default handles valid and partially invalid TSX; a failing custom syntax adapter cannot abort the scan and leaves explicit fallback/evidence diagnostics while TypeScript remains authoritative | Coupling core indexing to one optional parser or allowing extension failures to erase compiler results           |
| Compiler parser identity         | Omitting the parser and explicitly passing `createTypeScriptParserAdapter()` produce byte-identical managed artifacts and manifest identity without a rewrite                                                       | Running a second syntax traversal for the explicit built-in adapter or recording a different cache identity      |
| Persisted alpha artifacts        | `overview.md`, `manifest.json`, `files.jsonl`, `symbols.jsonl`, `relations.jsonl`, and `diagnostics.json` are deterministic; `project.json` is tolerated as an extra                                                | Missing human overview, timestamps in deterministic files, unstable ordering, or unconditional rewrites          |
| Aggregate persistence integrity  | `loadCodeMap` rejects individually valid records whose project counts or file-to-symbol ownership disagree with the aggregate map                                                                                   | Validating each JSON/JSONL record independently while accepting cross-record corruption                          |
| Evidence and hashes              | File/source/manifest hashes agree; relation confidence is bounded; locations and evidence point to root-relative source                                                                                             | Relations with no provenance, invalid confidence, or stale hashes                                                |
| Evidence classification          | Compiler facts identify exact `typescript-node` origins while framework inference identifies `framework-derived` React origins                                                                                      | Giving all relations the same provenance label or attributing derived JSX edges to the compiler                  |
| Incremental lifecycle            | Added, modified, deleted, and moved paths make the map stale with reasons; rescans remove obsolete records and orphan relations                                                                                     | Checking only existing mtimes, leaving tombstones, or reporting a same-content move only as unrelated add/delete |
| Compatibility freshness          | Configuration and analyzer changes stale the map; an incompatible schema gives an actionable rescan instruction                                                                                                     | Freshness based only on source bytes or opaque schema failures                                                   |
| Fault isolation and privacy      | Parse and unresolved-import diagnostics do not abort a normal scan; `.env`, arbitrary source literals, outside-root content, source files, and unrelated `.ai` files remain untouched                               | Fail-fast parsing, source execution, secret capture, broad `.ai` cleanup, or source mutation                     |
| Selected package isolation       | Scanning a child package selected inside a parent pnpm workspace indexes and persists only that child, never sibling package metadata or sources                                                                    | Searching ancestors with manypkg and silently expanding a child scan to the parent workspace                     |
| Ignore and path containment      | A nested `.gitignore` cannot reinclude content beneath an ignored parent, and escaped, backslash-traversal, drive-root, and absolute candidates are rejected without throwing                                       | Applying nested negation below an excluded directory or resolving attacker-controlled candidates outside root    |
| Generated schema synchronization | The repository command `pnpm schema:check` succeeds against checked-in JSON schemas                                                                                                                                 | Editing Zod source schemas without regenerating the committed schema artifacts                                   |
| Programmatic API                 | Init, scan, load, analyzer construction, and freshness checks work without calling `process.exit`                                                                                                                   | Sharing CLI exit behavior with library code                                                                      |
| CLI alpha flow                   | `init`, `scan`, `check`, and `show <symbol>` expose help/root/config/output options; current/stale/strict/config outcomes use 0/2/3/1                                                                               | Missing nested-root discovery, a non-inspectable show command, stack traces by default, or collapsed exit codes  |

Boundary cases include an anonymous default export, renamed imports and exports, duplicate names in separate files, overloaded functions, a class method, nested-directory CLI invocation, scan without prior init, invalid configuration, invalid source, an unknown external import, an arbitrary source literal, and a symlink whose target is outside the project root.

The suite deliberately does not impose timing thresholds, exact diagnostic prose, private helper structure, a cloud service, natural-language query/context commands, impact/statistics commands, or any source execution. Next.js and NestJS fixtures remain as opt-in post-alpha checks, enabled with `AI_CODE_MAP_TEST_OPTIONAL_FRAMEWORKS=1`; they are skipped in the gating alpha suite.

For in-repository type checking, fixture TypeScript files carry `// @ts-nocheck`. The fixture-copy helper removes that line before each scan so parse and unresolved-import behavior is tested against the real source form.
