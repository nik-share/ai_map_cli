# Independent alpha behavioral test contract

These tests derive their expectations from the user’s narrowed alpha request, not from the current implementation. They exercise public API calls, CLI subprocesses, and persisted artifacts. Fixture projects intentionally omit installed application dependencies: a local static analyzer must inspect syntax without executing fixture code.

## Gating alpha scenarios and faults rejected

| Scenario                         | Observable contract                                                                                                                                                                                                 | Example faulty implementation rejected                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| TypeScript/JavaScript discovery  | Selected TS, TSX, JS, and JSX files use root-relative POSIX paths; excluded files and outside-root symlinks do not enter the map                                                                                    | Recursive walking that follows symlinks, includes `.ai`/build output, or stores absolute paths                   |
| Exact core index                 | Imports, renamed imports, exports/re-exports, CommonJS, public signatures, environment-variable names, references/calls, classes/methods, source locations, and stable unique IDs are present                       | Regex-only parsing that loses aliases, overloads, calls, class qualification, or duplicate names                 |
| React index                      | Typed component props, `useState`, `useReducer`, `useMemo`, `useCallback`, `useEffect`, dependency arrays, memo wrapping, and rendered JSX edges are represented                                                    | Merely labeling capitalized functions as components without state/hook/dependency/render evidence                |
| Parser adapter boundary          | The compiler-backed default handles valid and partially invalid TSX; a failing custom syntax adapter cannot abort the scan and leaves explicit fallback/evidence diagnostics while TypeScript remains authoritative | Coupling core indexing to one optional parser or allowing extension failures to erase compiler results           |
| Compiler parser identity         | Omitting the parser and explicitly passing `createTypeScriptParserAdapter()` produce byte-identical managed artifacts and manifest identity without a rewrite                                                       | Running a second syntax traversal for the explicit built-in adapter or recording a different cache identity      |
| Persisted alpha artifacts        | `overview.md`, `manifest.json`, `files.jsonl`, `symbols.jsonl`, `relations.jsonl`, and `diagnostics.json` are deterministic; `project.json` is tolerated as an extra                                                | Missing human overview, timestamps in deterministic files, unstable ordering, or unconditional rewrites          |
| Aggregate persistence integrity  | `loadCodeMap` rejects individually valid records whose project counts or file-to-symbol ownership disagree with the aggregate map                                                                                   | Validating each JSON/JSONL record independently while accepting cross-record corruption                          |
| Evidence and hashes              | File/source/manifest hashes agree; relation confidence is bounded; locations and evidence point to root-relative source                                                                                             | Relations with no provenance, invalid confidence, or stale hashes                                                |
| Evidence classification          | Compiler facts identify exact `typescript-node` origins while framework inference identifies `framework-derived` React origins                                                                                      | Giving all relations the same provenance label or attributing derived JSX edges to the compiler                  |
| Incremental lifecycle            | Added, modified, deleted, and moved paths make the map stale with reasons; rescans remove obsolete records and orphan relations                                                                                     | Checking only existing mtimes, leaving tombstones, or reporting a same-content move only as unrelated add/delete |
| Compatibility freshness          | Configuration and analyzer changes stale the map; an incompatible schema gives an actionable rescan instruction                                                                                                     | Freshness based only on source bytes or opaque schema failures                                                   |
| Fault isolation and privacy      | Parse and unresolved-import diagnostics do not abort a normal scan; `.env`, arbitrary source literals, outside-root content, source files, and unrelated `.ai` files remain untouched                               | Fail-fast parsing, source execution, secret capture, broad `.ai` cleanup, or source mutation                     |
| Selected package isolation       | Scanning a child package selected inside a parent pnpm workspace indexes and persists only that child, never sibling package metadata or sources                                                                    | Searching ancestors with manypkg and silently expanding a child scan to the parent workspace                     |
| Ignore and path containment      | A nested `.gitignore` cannot reinclude content beneath an ignored parent, and escaped, backslash-traversal, drive-root, and absolute candidates are rejected without throwing                                       | Applying nested negation below an excluded directory or resolving attacker-controlled candidates outside root    |
| Generated schema synchronization | The repository command `pnpm schema:check` succeeds against checked-in JSON schemas                                                                                                                                 | Editing Zod source schemas without regenerating the committed schema artifacts                                   |
| Programmatic API                 | Init, scan, load, analyzer construction, and freshness checks work without calling `process.exit`                                                                                                                   | Sharing CLI exit behavior with library code                                                                      |
| CLI alpha flow                   | `init`, `scan`, `check`, and `show <symbol>` expose help/root/config/output options; current/stale/strict/config outcomes use 0/2/3/1                                                                               | Missing nested-root discovery, a non-inspectable show command, stack traces by default, or collapsed exit codes  |

Boundary cases include an anonymous default export, renamed imports and exports, duplicate names in separate files, overloaded functions, a class method, nested-directory CLI invocation, scan without prior init, invalid configuration, invalid source, an unknown external import, an arbitrary source literal, and a symlink whose target is outside the project root.

The suite deliberately does not impose timing thresholds, exact diagnostic prose, private helper structure, a cloud service, natural-language query/context commands, impact/statistics commands, or any source execution. Next.js regression tests run in the default suite, including CLI auto-selection, explicit opt-out, `src` router parity, layout links, destructured handlers, and wrapped exports. The legacy Next.js and NestJS fixture checks can also be run with `AI_CODE_MAP_TEST_OPTIONAL_FRAMEWORKS=1`.

For in-repository type checking, fixture TypeScript files carry `// @ts-nocheck`. The fixture-copy helper removes that line before each scan so parse and unresolved-import behavior is tested against the real source form.

## Milestone 1 compiler-unit behavioral contract

These scenarios derive from the original Milestone 1 request. They observe only `scanProject`, `checkFreshness`, `loadCodeMap`, CLI results, and persisted records/artifact bytes. They do not assert discovery helper call order, TypeScript `Program` identity, or private coordinator structure.

| Scenario                          | Observable contract                                                                                                                                                                                                                                                                                                                                                           | Boundary or failure case                                                                                                                                                   | Plausible faulty implementation rejected                                                                                                                                                             |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CWD and ambient-type independence | With identical absolute root/config/output inputs, a forced-fresh full analysis launched from the target and two unrelated directories produces byte-identical managed artifacts. Each immediate unchanged follow-up has empty changes and `wrote: false`; persisted content contains no absolute fixture, caller, or outside paths.                                          | The project contains one valid root `@types` package that must remain loaded, while each unrelated caller contains a conflicting ambient declaration that must be ignored. | Comparing only fast-path reuse across CWDs, or leaving `CompilerHost.getCurrentDirectory`, implicit `typeRoots`, module resolution, or `getDirectories` basename containment anchored to the caller. |
| Workspace-local aliases           | Two workspace packages using the same alias spelling resolve imports, calls, references, and JSX/render targets to their own root-relative files and symbols.                                                                                                                                                                                                                 | The alias text is identical while each package has a different `baseUrl`/`paths` target.                                                                                   | Flattening all configs into one options object or globally caching resolution by module specifier alone.                                                                                             |
| Project-reference semantics       | An application referencing a library resolves imports, calls, constructions, definitions/references, and re-exports across the unit boundary without duplicate files, symbols, or relations.                                                                                                                                                                                  | A solution-style root config owns no files directly and the referenced library is also visible through the application `Program`.                                          | Analyzing every file returned by every `Program`, or discarding cross-project checker targets during per-unit normalization.                                                                         |
| Browser/tooling ownership         | Browser source and Node/tooling source in one package have exactly one inspectable owner each, and each owner is an eligible config whose parsed file set includes the file.                                                                                                                                                                                                  | A root browser config excludes the tooling file while a sibling `tsconfig.node.json` includes only that tooling file.                                                      | Selecting one root tsconfig for every discovered source, or assigning a file to a config that does not include it.                                                                                   |
| Deterministic overlap precedence  | A file included by overlapping configs has one owner: the most specific applicable package/project boundary wins, with normalized lexical config path only as the final tie-breaker. The result is stable across scans and independent of config creation/discovery order.                                                                                                    | Equally specific overlapping configs force the documented lexical tie-break; a nested package boundary tests specificity before lexical order.                             | First-match ownership based on `readdir`, glob, object insertion, or project-reference traversal order.                                                                                              |
| Explicit fallback unit            | An indexed JS/TS file included by no eligible config is analyzed once under one inspectable root-anchored fallback unit and still contributes core semantic records.                                                                                                                                                                                                          | All real configs exclude the orphan.                                                                                                                                       | Silently dropping unowned files, injecting them into an arbitrary config, or creating one fallback `Program` per file.                                                                               |
| Complete semantic freshness       | Mutating a transitively extended config, a referenced config, or an applicable sibling config makes `checkFreshness` stale without requiring a source edit. Mutating relevant workspace dependency metadata or a relevant lockfile also makes it stale.                                                                                                                       | Each input is changed independently and restored by a rescan; `changes` may remain empty because these are non-source semantic inputs.                                     | Hashing only the selected root tsconfig, dependency names without ranges, or scan-only unit inputs that `check` does not share.                                                                      |
| Bounded config graph and symlinks | Out-of-root `references`, `extends`, config symlinks, and source symlinks are rejected or safely diagnosed, never index outside content, never persist outside secrets/absolute paths, and never execute configuration/source code.                                                                                                                                           | Escape attempts include absolute paths, `..` traversal, and symlinks; a marker write would reveal execution.                                                               | Trusting parsed reference paths without realpath containment, enabling symlink traversal, or loading configuration with dynamic import/`require`.                                                    |
| Stable unchanged lifecycle        | An unchanged rescan preserves the semantic fingerprint and every managed artifact byte and mtime while reporting empty changes and `wrote: false`; `checkFreshness` reports current.                                                                                                                                                                                          | Output location is explicit and remains constant across callers.                                                                                                           | Separate scan/check fingerprint implementations, timestamps in artifacts, or unconditional persistence.                                                                                              |
| Validated unchanged-map reuse     | An unchanged default scan returns the complete validated map with empty changes and `wrote: false` without invoking the parser, semantic resolver, or framework analyzers again. Any source/config/package/lock/tool staleness or invalid/missing managed artifact falls through to full analysis and repairs the map; custom component identities never reuse a default map. | Reuse is tested separately for valid defaults, eight stale/corrupt inputs, and each custom parser/analyzer/resolver identity.                                              | Trusting only `manifest.json`, returning a partial result, skipping artifact validation, reusing stale semantic inputs, or treating a custom scan as equivalent to the default toolchain.            |
| Alpha compatibility and non-goals | The existing API, CLI, schema, security, determinism, core, React, and optional-framework suites remain green. Default scans retain Core and React behavior; Next.js follows framework selection and NestJS stays opt-in; no MCP/watch/cloud/NL/Tree-sitter production behavior is introduced.                                                                                | Custom semantic-resolver compatibility follows the documented public contract or an explicit compatibility adapter.                                                        | Replacing the existing public flow, enabling NestJS by default, weakening security invariants, or promoting the development parser prototype.                                                        |

### Required invariants across compiler-unit scenarios

- Every indexed JS/TS path appears once in `files.jsonl`, every symbol ID is unique, every relation record is unique, and each file has exactly one inspectable compiler-unit owner.
- Unit IDs, config paths, owner paths, import targets, symbol IDs, relation endpoints, evidence, diagnostics, and freshness inputs use normalized selected-root-relative logical identity; absolute paths, `Program` objects, AST nodes, and checker objects never enter artifacts.
- Ownership eligibility is proven by the config's parsed inclusion rather than directory ancestry alone. Workspace/project specificity precedes lexical tie-breaking, and discovery order has no semantic effect.
- Cross-unit semantic normalization preserves Core and React relations while avoiding duplicate contributions from overlapping programs.
- Config, source, manifest, and lockfile reads stay inside the selected real root; normal scanning performs no network access and executes no source, package scripts, runtime reflection, or configuration code.

## Milestone 1.1 semantic correctness and freshness hardening contract

These guarantees extend the Milestone 1 contract. Tests observe `scanProject`, `checkFreshness`, `loadCodeMap`, CLI results, and canonical artifact bytes. Source/configuration plus the built-in pipeline are authoritative; persisted records are reusable only when the manifest commit marker, producer identity, companion-artifact hashes, schemas, and cross-record invariants all agree.

The minimum complete map is `overview.md`, `manifest.json`, `project.json`, `files.jsonl`, `symbols.jsonl`, `relations.jsonl`, and `diagnostics.json`. `config.json` is an analysis input, not a companion map artifact.

| Scenario                                    | Observable outcome and boundary/failure behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Plausible faulty implementation rejected                                                                                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Imported semantic input closure             | Changing an in-root source that a configured Program consumes but the scanner does not index makes `check` non-current; the next ordinary scan performs analysis and updates any affected public signature or relation. The bounded closure includes raw-byte file hashes, project/toolchain-scoped file/directory/readability probes, observed child-directory listings and symlink mappings, and exact consumed TypeScript library bytes—not a repository-wide file hash. Missing or unreadable TypeScript-library candidates remain distinct from project probes so same-version restoration cannot evade freshness. | Hashing only `files.jsonl`/`manifest.sourceFiles`, tracking successful reads but not failed/directory/toolchain lookups, or trusting only a TypeScript version string.              |
| Package-scope resolution inputs             | Changing a nested `package.json` field that TypeScript used for `imports`, `exports`, `types`, or module resolution makes the map stale and recomputes the affected import/relation target. Relevant missing package-scope probes are tracked when their later appearance could alter resolution.                                                                                                                                                                                                                                                                                                                       | Hashing only the root/workspace manifests, or treating package metadata as dependency-name display data rather than compiler input.                                                 |
| Complete artifact validation                | `check` never reports `current: true` when any minimum companion is missing, unreadable, invalid JSON/JSONL, schema-invalid, hash-mismatched, incompatible, or inconsistent with the other records. `scan` repairs such a map through full analysis.                                                                                                                                                                                                                                                                                                                                                                    | Trusting a valid/current `manifest.json` without opening and validating every committed companion.                                                                                  |
| Canonical byte hashing                      | Both initial scan and later freshness checks calculate SHA-256 over the exact raw file bytes. Invalid UTF-8 may be decoded for parsing with replacement characters, but never defines freshness.                                                                                                                                                                                                                                                                                                                                                                                                                        | Hashing decoded text during scan and `Buffer` bytes during check, causing permanent false staleness.                                                                                |
| Excluded JavaScript fallback                | An indexed `.js`/`.jsx` file omitted by an apparent config (including `allowJs: false`) is analyzed exactly once by the root-anchored fallback; `.ts`/`.tsx` ownership remains config-driven. A portable per-file diagnostic explains fallback use.                                                                                                                                                                                                                                                                                                                                                                     | Assigning by directory ancestry and then silently producing an empty file because `Program.getSourceFile` omitted it.                                                               |
| Real project-reference package import       | A composite application reference importing a sibling package through that package's metadata/types entry, with no direct source `paths` alias, resolves to the referenced source and emits internal semantic relations without requiring prebuilt declarations.                                                                                                                                                                                                                                                                                                                                                        | Merely fingerprinting `references`, or resolving only because a fixture aliases directly to `../package/src`.                                                                       |
| Collision-safe unit identity                | Configured unit IDs and generated/reserved unit IDs occupy structurally distinct namespaces. A real configured path named `fallback` and the generated fallback are unique and deterministic.                                                                                                                                                                                                                                                                                                                                                                                                                           | Using `compiler-unit:${configPath}` beside a reserved `compiler-unit:fallback` string.                                                                                              |
| Portable persistence                        | No selected-root, repository-parent, temporary-directory, POSIX absolute host path, Windows drive/UNC path, or unresolved absolute import specifier appears in any canonical artifact, diagnostic, relation endpoint/evidence, compiler-unit identity, signature, or fact. Path recognition is host-independent, including path text contributed by custom components. Supplied analyzers receive isolated persistence context unless they have a non-spoofable registered built-in identity resolved at invocation time.                                                                                               | Applying `path.isAbsolute` on macOS/Linux to Windows syntax, sanitizing only file-record paths, trusting custom fact strings, or caching a Proxy-spoofable analyzer trust decision. |
| External module provenance                  | When an import/checker declaration proves a module, external calls use that module plus exported/member identity (for example `external:react#useState`), never a local alias/variable as the module. Unproven targets remain explicitly `external:unresolved#...`; exact and heuristic evidence remain distinguishable.                                                                                                                                                                                                                                                                                                | Producing `external:useState#useState`, `external:router#push`, or claiming an unresolved syntactic guess is exact.                                                                 |
| Default-import React rendering              | JSX through a default import resolves to the actual indexed component symbol and emits one `renders` relation, even when TypeScript's aliased symbol is named `default`.                                                                                                                                                                                                                                                                                                                                                                                                                                                | Building the target ID from `getAliasedSymbol(...).getName()` without recovering the declaration's logical name.                                                                    |
| Semantic relation uniqueness                | At most one normalized relation exists for a given from/type/to/evidence range. Competing contributions choose the strongest deterministic record while distinct call sites, including two on one line, remain distinct. Persisted-map validation rejects duplicates.                                                                                                                                                                                                                                                                                                                                                   | De-duplicating only byte-identical JSON, retaining cross-unit duplicates, or collapsing every same-line call site.                                                                  |
| Provenance-safe default reuse and integrity | Only maps centrally marked as produced by the built-in pipeline with the expected stable producer/capability/configuration fingerprints can take the default fast path. Supplying custom components marks the result custom even if names/versions spoof built-ins. Companion raw-byte hashes detect schema-valid tampering, while a manifest integrity hash binds producer and semantic-input metadata. The integrity index is tamper-evident, not a cryptographic signature against an actor able to rewrite the whole map.                                                                                           | Comparing mutable display names/versions alone, accepting coherent-looking companion edits without hashes, or leaving manifest metadata unbound.                                    |
| Cross-record semantic integrity             | A complete artifact set loads only when canonical compiler-unit IDs/references, file and symbol ownership, import targets and matching import relations, counts, source hashes, endpoints, line/range bounds, evidence origins, and containment/export ownership agree. Ordinary scans repair rejected candidates.                                                                                                                                                                                                                                                                                                      | Validating each JSON record independently while accepting a schema-valid ghost import, moved evidence, arbitrary compiler-unit ID, or out-of-bounds range.                          |

### Milestone 1.1 unchanged behavior and operational bounds

- Canonical ordering, CWD independence, existing React/Next.js/TypeScript/Node.js/NestJS behavior, public CLI exit semantics, source safety, schema validation, and user-owned files remain unchanged except for documented correctness diagnostics and a justified schema bump.
- A valid unchanged default map still avoids parser, Program, and analyzer construction and remains substantially faster than a fresh scan.
- Semantic closure collection is bounded to compiler-consumed files, typed resolution/configuration probes and observed directories/symlinks scoped to the selected project or active TypeScript library root, and exact consumed TypeScript library files; it never hashes every repository file blindly.
- Real-project validation writes outputs outside the three target repositories, records both target Git states, and inspects relation examples rather than treating relation-count growth as quality evidence.

## Milestone 1.1.1 correctness-closure contract

These scenarios derive from the Milestone 1.1.1 request and observe public scans, loads, freshness,
canonical bytes, and benchmark grouping. They do not require a particular private checker walk.

| Behavioral unit                     | Observable contract                                                                                                                                                                                 | Plausible faulty implementation rejected                                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Exact import provenance             | Only the checker-bound import declaration can prove an external module; local imports and shadowed identifiers never become exact package IDs, while an unshadowed package import remains exact.    | Matching call identifiers to import text without verifying symbol identity or `external: true`.     |
| Occurrence evidence                 | JSX renders and custom-hook calls at distinct full ranges persist separately, including same-line columns; competing contributions at one range collapse deterministically.                         | Deduplicating candidates by lowercased name before normalization.                                   |
| Byte repair and canonical integrity | Artifact equality is byte-for-byte; an ordinary scan repairs invalid UTF-8 bytes, and coherent-corruption tests use the production canonical integrity helper before reaching aggregate validation. | Comparing decoded strings or using locale-dependent test serialization.                             |
| Persisted ownership truth           | Manifest source ownership and line counts agree with `files.jsonl`; direct load rejects a one-sided coherent fallback reassignment or line-count rewrite.                                           | Checking only that `file.compilerUnit` names some existing unit.                                    |
| Portable identifiers                | Foreign absolute/traversing aliases and custom host/file-URI identifiers never persist; relative wildcards and `/users/:id` survive. Invalid custom output cannot abort built-in analysis.          | Applying host-native `path.resolve` before foreign-syntax detection or exempting every `route:` ID. |
| Reference and fallback completeness | Composite root-level referenced sources resolve without declarations; explicit `rootDir: src` remains; every fallback-owned JS/JSX-family file is analyzed once with a portable reason.             | Assuming every reference source lives under `src`, or diagnosing only `allowJs: false`.             |
| Honest unresolved audit             | A relation is unresolved when either endpoint carries unresolved identity; derived inverse records remain uncertain and do not inflate resolved internal coverage.                                  | Classifying inverse relations only from their internal `to` endpoint.                               |

Schema v4 is a deliberate rescan boundary for redundant manifest ownership/line records. Integrity is
tamper-evident, not authenticated against an actor rewriting every redundant record and hash.
